# Pathquill

Private technical exploration of a bounded Linux network incident recorder.
No project license has been selected. This is a minimal production-core candidate,
not a complete daemon or qualified MVP.

The original core is imported by tests; no alternate implementation is used.
The Linux runner exercises an isolated network namespace inside a Colima VM,
then drops to UID 501 before opening the route notification socket. Root only
creates the disposable namespace and dummy interface. The namespace disappears
when the runner and helper processes exit.

## Reproduce

Python 3.12+ on Linux, iproute2, sudo and unshare are required. From this checkout:

```sh
python3 -m unittest discover -s tests -t . -v
sudo unshare --net python3 tools/explore.py --uid "$(id -u)" --output evidence/exploration.json
```

Run only inside a disposable Linux VM. The Linux runner creates a dummy link,
executes the tests, observes a real link notification as an ordinary account,
and kills a child after its incident transaction commits. JSON and HTML contain
the same result data. Nonzero exit means failed exploration. Full process or
external command hangs are not yet guarded by an outer qualification timeout.

[Observed JSON](evidence/exploration.json), [HTML](evidence/exploration.html),
[architecture and acceptance decisions](docs/ARCHITECTURE.md).

## Boundaries

No persistent pre-event ring, snapshot/dump reconciliation, full Netlink attribute
decoder, automatic probe scheduler, DNS client, retention policy, export file
publication, systemd packaging or complete service lifecycle exists yet.
The core only stores the trigger payload, not every observation in its window.
Its watermark argument is a caller contract, not a qualified end-to-end barrier.
Export returns an in-memory allowlisted JSON/HTML pair; it has no source-file
pin/GC race because file publication has not been implemented.

The report distinguishes actual kernel notifications and process SIGKILL from
injected loss metadata, synthetic times and connection-level query_only failure.
SQLite FULL is generated by the real database page limit; this is not a physical
filesystem ENOSPC test. VM reboot, sudden power loss, suspend, wall-clock changes,
actual kernel ENOBUFS and long-running resource stability are untested.

No performance or complete network-diagnosis claims are made. The local raw
SQLite store can contain sensitive identifiers; exports omit arbitrary fields,
but this is not a complete anonymization system. Runtime dependencies are Python
standard library; Linux, Python and SQLite retain their own licensing terms.
